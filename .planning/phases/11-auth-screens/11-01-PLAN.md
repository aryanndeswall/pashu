<threat_model>
| Threat ID | Category | Component | Description | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-11-01 | State Loss | Auth Store | App termination or OS reboot corrupting login progress or losing user credentials in offline environments | Persist session tokens and user credentials to SQLite `user_credentials` and `auth_session` tables on each step. |
| T-11-02 | Input Injection / Tampering | Login View | Malformed telephone numbers or invalid license strings causing runtime exceptions | Apply strict Indian mobile regex `^[6-9]\d{9}$` and role-specific validation before dispatching OTP. |
| T-11-03 | Replay / Brute Force | OTP Screen | Automated brute-force attacks on 6-digit OTP inputs | Enforce 30-second rate-limiting cooldown and maximum 5 verification attempts per session. |
</threat_model>

  <files>mobile/src/database/migrations.ts, mobile/src/database/sqliteConnection.ts, mobile/src/store/authStore.ts</files>
  <read_first>mobile/src/database/migrations.ts, mobile/src/database/sqliteConnection.ts, mobile/src/store/authStore.ts, .planning/phases/11-auth-screens/11-RESEARCH.md</read_first>
  <action>
    1. In `mobile/src/database/migrations.ts`, add DDL for `user_credentials` and update `auth_session`:
       ```sql
       CREATE TABLE IF NOT EXISTS user_credentials (
         id TEXT PRIMARY KEY,
         role TEXT NOT NULL,
         full_name TEXT NOT NULL,
         mobile_hash TEXT NOT NULL,
         mobile_masked TEXT NOT NULL,
         license_or_id TEXT,
         district TEXT NOT NULL,
         block TEXT NOT NULL,
         village TEXT,
         offline_pin_hash TEXT,
         created_at TEXT NOT NULL,
         updated_at TEXT NOT NULL
       );
       ```
    2. In `mobile/src/database/sqliteConnection.ts`, register `user_credentials` in the in-memory fallback map `memoryTables` and support `INSERT`, `UPDATE`, and `SELECT` queries for `user_credentials`.
    3. In `mobile/src/store/authStore.ts`, extend `AuthState` and `UserProfile`:
       - Add types:
         - `LoginStep = 'portal' | 'login' | 'otp' | 'onboarding' | 'pin_setup' | 'pin_unlock' | 'authenticated'`
       - Add state properties:
         - `isAuthenticated: boolean` (default `false`)
         - `loginStep: LoginStep` (default `'portal'`)
         - `pendingPhone: string`
         - `pendingSecondaryId: string`
         - `otpError: string | null`
         - `otpCountdown: number`
         - `isLocked: boolean`
         - `hasOfflinePin: boolean`
       - Add actions:
         - `setLoginStep(step: LoginStep): void`
         - `selectRoleAndProceed(role: UserRole): void`: sets `activeRole`, updates `loginStep` to `'login'`, emits light haptic.
         - `requestOtp(phone: string, secondaryId?: string): Promise<boolean>`: validates 10-digit phone, stores pending info, starts 30s timer, transitions `loginStep` to `'otp'`.
         - `verifyOtp(enteredOtp: string): Promise<boolean>`: verifies 6-digit OTP (accepts simulated code or `'123456'`), transitions to `'onboarding'` if new user or `'pin_unlock'`/`'authenticated'` if existing.
         - `logout(): Promise<void>`: clears session in SQLite, resets `isAuthenticated: false`, `loginStep: 'portal'`.
  </action>
  <verify>
    Run `npm --prefix mobile test -- --run src/tests/authStore.test.ts` to confirm existing store operations still pass without regressions.
  </verify>
