<threat_model>
| Threat ID | Category | Component | Description | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-01-03 | Information Disclosure | Native SQLite Storage | Unencrypted local database accessed on rooted or shared devices | Configure SQLCipher encryption key via Capacitor SQLite plugin; store database in protected app data directory. |
| T-01-04 | Data Loss / Tampering | Schema Migration | Corrupted SQLite schema on app update resulting in unrecoverable reports | Use versioned, idempotent DDL migrations (`CREATE TABLE IF NOT EXISTS`) and transactional table upgrades. |
</threat_model>

<task type="auto">
  <name>Task 1: Implement Native SQLite Connection Service and Schema Migrations</name>
  <files>mobile/src/database/sqliteConnection.ts, mobile/src/database/migrations.ts, mobile/package.json</files>
  <read_first>mobile/capacitor.config.ts, .planning/phases/01-project-scaffolding-native-android-apk-foundation/01-CONTEXT.md</read_first>
  <action>
    Install and configure the native SQLite database plugin and build migration logic.
    1. In `mobile/package.json`, install `@capawesome-team/capacitor-sqlite` (or `@capacitor-community/sqlite`).
    2. Create `mobile/src/database/sqliteConnection.ts`:
       - Define database name as `"pashu_offline.db"` located in default protected storage (`/data/data/com.pashusuraksha.app/databases/`).
       - Provide singleton connection manager: `initDatabase()`, `getDatabase()`, `executeSql(statement, values)`, `querySql(query, values)`.
       - Include web browser fallback mock so developers running `npm run dev` in browser can test without native Android failures.
    3. Create `mobile/src/database/migrations.ts` with idempotent DDL:
       - `local_lgd_hierarchy`: `lgd_code INTEGER PRIMARY KEY, village_name TEXT NOT NULL, block_name TEXT NOT NULL, district_name TEXT NOT NULL, latitude REAL NOT NULL, longitude REAL NOT NULL`
       - `local_animals`: `tag_number TEXT PRIMARY KEY, owner_name TEXT NOT NULL, owner_mobile_masked TEXT NOT NULL, species TEXT NOT NULL, breed TEXT, village_lgd_code INTEGER NOT NULL, vaccination_status TEXT, last_synced_at TEXT NOT NULL`
       - `offline_sync_queue`: `sync_id TEXT PRIMARY KEY, entity_type TEXT NOT NULL, payload_json TEXT NOT NULL, priority INTEGER DEFAULT 1, status TEXT DEFAULT 'PENDING', retry_count INTEGER DEFAULT 0, created_at TEXT NOT NULL`
       - Create indexes: `idx_sync_status ON offline_sync_queue(status, priority)`, `idx_local_animals_village ON local_animals(village_lgd_code)`.
  </action>
  <verify>
    Run `npm --prefix mobile run build` and ensure TypeScript compiles with zero type errors in database service.
  </verify>
  <acceptance_criteria>
    - `mobile/src/database/sqliteConnection.ts` contains `pashu_offline.db`

    - `mobile/src/database/migrations.ts` contains `CREATE TABLE IF NOT EXISTS offline_sync_queue`
  </acceptance_criteria>
  <done>
    Native SQLite connection manager and DDL migrations are implemented with web fallback.
  </done>
