<threat_model>
| Threat ID | Category | Component | Description | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-05-01 | Bandwidth Starvation | syncEngineService | Large WebP or audio files uploaded over 2G causing socket timeout, battery drain, and dropped telemetry | Block Phase 2 binary payload uploads when network is CELLULAR_2G_EDGE or OFFLINE. |
| T-05-02 | Data Loss | offline_sync_queue | Outbreak incident reports dropped if network fails mid-upload | Update SQLite status transactionally: PENDING -> PHASE_1_SYNCED -> COMPLETED. Never delete unverified reports. |
| T-05-03 | SMS Corruption | smsFallbackService | SMS packets truncated by carrier without detection | Append a 4-character hex CRC-16 checksum to every SMS message. |
</threat_model>

    2. Create `mobile/src/types/sync.ts`:
       - `NetworkTier = 'OFFLINE' | 'CELLULAR_2G_EDGE' | 'CELLULAR_4G_5G' | 'WIFI'`
       - `SyncPhase = 'PHASE_1_TELEMETRY' | 'PHASE_2_MEDIA'`
       - `QueueStatus = 'PENDING' | 'PHASE_1_SYNCED' | 'COMPLETED' | 'FAILED_RETRY'`
       - `Phase1TelemetryPayload`:
         `{ sync_id: string; report_id: string; syndrome_code: string; secondary_symptoms: string[]; differential?: string | null; coordinates: { latitude: number; longitude: number }; lgd_code: number; village_name: string; district_name: string; pashu_aadhaar?: string; reported_at: string; has_photo: boolean; has_audio: boolean; priority: number; }`

         `{ sync_id: string; report_id: string; photo_webp?: string | null; audio_base64?: string | null; }`
       - `QueueItem`:
         `{ sync_id: string; entity_type: string; payload_json: string; priority: number; status: QueueStatus; retry_count: number; created_at: string; synced_at?: string | null; }`
    3. Create `mobile/src/services/networkService.ts`:
       - Wraps `@capacitor/network` `Network.getStatus()` and `Network.addListener('networkStatusChange')`.
       - Integrates `navigator.connection?.effectiveType` and browser events for web fallback.
       - Maps status to `NetworkTier`:
         - `!connected` -> `'OFFLINE'`
         - `connectionType === 'wifi'` -> `'WIFI'`
         - `connectionType === 'cellular'`:
           - If `effectiveType === '2g'` or `'slow-2g'` -> `'CELLULAR_2G_EDGE'`
           - Else -> `'CELLULAR_4G_5G'`
         - Unknown fallback: if connected, default to `'CELLULAR_4G_5G'`.
       - Provides manual simulation setter `setSimulatedNetwork(tier: NetworkTier | null)` for testing and demo toggle.
       - Exposes `getNetworkState(): Promise<NetworkTier>` and `onNetworkChange(callback: (tier: NetworkTier) => void): () => void`.
    4. Create `mobile/src/tests/networkService.test.ts`:
       - Tests default offline/online detection.
       - Tests mapping to 4 network tiers.
       - Tests simulated network override and change listener dispatches.

  <files>mobile/src/services/syncEngineService.ts, mobile/src/services/smsFallbackService.ts, mobile/src/tests/syncEngine.test.ts, mobile/src/tests/smsFallbackService.test.ts</files>

  <action>
    1. Create `mobile/src/services/syncEngineService.ts`:
       - `extractPhase1Payload(rawRecord: any): Phase1TelemetryPayload`:
         - Strips `photo_webp` and `audio_base64`.
         - Retains coordinates, syndrome, symptoms, LGD village code, pashu_aadhaar, and priority.
         - Sets `has_photo: Boolean(rawRecord.photo_webp)` and `has_audio: Boolean(rawRecord.audio_base64)`.
       - `extractPhase2Payload(rawRecord: any): Phase2MediaPayload | null`:
         - Returns `{ sync_id, report_id, photo_webp, audio_base64 }` if any media exists, or `null`.
       - `processSyncQueue(currentTier: NetworkTier): Promise<{ syncedPhase1: number; syncedPhase2: number; failed: number }>`:
         - If `currentTier === 'OFFLINE'`, returns early `{ syncedPhase1: 0, syncedPhase2: 0, failed: 0 }`.
         - Reads `SELECT * FROM offline_sync_queue WHERE status != 'COMPLETED' ORDER BY priority DESC, created_at ASC`.
         - For each record:
           - If status is `PENDING`:
             - Dispatches Phase 1 telemetry to endpoint (mock API client returning success in <50ms).
             - Updates SQLite record status:
               - If no media exists: status ➔ `'COMPLETED'`, `synced_at` = current timestamp.
               - If media exists: status ➔ `'PHASE_1_SYNCED'`.
           - If status is `PHASE_1_SYNCED`:
             - If `currentTier === 'CELLULAR_4G_5G' || currentTier === 'WIFI'`:
               - Dispatches Phase 2 binary payload.
               - Updates SQLite record status ➔ `'COMPLETED'`, `synced_at` = current timestamp.
             - If `currentTier === 'CELLULAR_2G_EDGE'`:
               - Skips Phase 2 binary upload (protects 2G connection).
         - Implements exponential backoff retry counters upon failure (`status = 'FAILED_RETRY'`, `retry_count += 1`).
    2. Create `mobile/src/services/smsFallbackService.ts`:
       - `calculateCrc16(text: string): string`: Computes 4-character hex checksum.
       - `generateSmsEmergencyPayload(record: any): string`:
         - Formats: `PS*<SYN_CODE>*<LGD_CODE>*<LAT,LNG>*<TAG_4DIGIT>*P<PRIORITY>*<CRC>`
         - Example: `PS*HSDS*558301*19.39,74.65*9012*P3*C4F1`
         - Validates total length <= 140 characters.
       - `createSmsUrl(smsText: string, recipient: string = '1962'): string`:
         - Returns `sms:${recipient}?body=${encodeURIComponent(smsText)}`.
       - `verifySmsPayload(smsText: string): boolean`:
         - Validates structure and CRC checksum match.
    3. Create tests:
       - `mobile/src/tests/syncEngine.test.ts`:
         - Tests `extractPhase1Payload` strips base64 media and keeps size < 1.5 KB.
         - Tests `processSyncQueue` in `CELLULAR_2G_EDGE` mode: Phase 1 gets promoted to `PHASE_1_SYNCED`, media is not uploaded.
         - Tests `processSyncQueue` in `WIFI` mode: Phase 1 and Phase 2 complete to `COMPLETED`.
         - Tests priority 3 records are processed first.
       - `mobile/src/tests/smsFallbackService.test.ts`:
         - Tests SMS generation length is strictly <= 140 characters.
         - Tests CRC checksum calculation and validation.
         - Tests SMS URI creation with recipient `1962`.
  </action>
