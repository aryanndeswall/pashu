<threat_model>
| Threat ID | Category | Component | Description | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-02-01 | Denial of Service | Haptics Service | Direct native Haptics calls throw unhandled exceptions in browser/unsupported environments | Wrap all Haptics invocations in `hapticsService.ts` with `Capacitor.isNativePlatform()` checks and graceful `navigator.vibrate` / no-op fallback. |
| T-02-02 | Configuration | AndroidManifest.xml | Missing VIBRATE permission causes silent failure of haptic feedback on Android devices | Add `<uses-permission android:name="android.permission.VIBRATE" />` to `AndroidManifest.xml`. |
| T-02-03 | Usability / Panic | SOS Button | Accidental taps on the center SOS button triggering false biohazard panic | Require an explicit button press, emit an unmistakable heavy alert vibration, and require user confirmation in the emergency modal. |
</threat_model>

       - `hapticLight()`: Light impact (`ImpactStyle.Light`) for tab switches and card selections.
       - `hapticMedium()`: Medium impact (`ImpactStyle.Medium`) for report saves and standard button clicks.
       - `hapticError()`: Heavy notification error pulse (`NotificationType.Error`) for Anthrax / SOS alerts.
       - Graceful fallback: check `Capacitor.isNativePlatform()`; if web, invoke `navigator?.vibrate?.([10])` where supported or no-op safely.
